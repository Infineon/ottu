# Coveralls Setup

This guide explains how to configure Coveralls for this repository so test coverage is uploaded automatically from GitHub Actions.

## Overview

The integration has two pieces:

1. Generate `coverage.xml` during the test workflow.
2. Upload `coverage.xml` to Coveralls from GitHub Actions.

This repository already uses `pytest` and `pytest-cov`, so we only need to ensure the workflow includes a coverage report and the Coveralls upload step.

## Prerequisites

1. A GitHub repository with Actions enabled.
2. A Coveralls account connected to GitHub.
3. `pytest-cov` installed (already present in this project).

## 1. Enable the repository in Coveralls

1. Sign in to [coveralls.io](https://coveralls.io) with GitHub.

> [!NOTE]
> The Coveralls integration is currently linked to the user account `jaenrig-ifx`. This is planned to be migrated to a team-managed account in the future.

 
2. Open your repositories list and enable this repository.
3. Confirm the repository appears as active in Coveralls.

Official docs: [Coveralls Documentation](https://docs.coveralls.io/index)

## 2. Ensure tests generate `coverage.xml`

In [pyproject.toml](../pyproject.toml), pytest options already include:

- `--cov=ottu`
- `--cov-report=xml`
- `--cov-report=term-missing`

In CI, you can either rely on those defaults or pass explicit flags in the test step.

## 3. Configure GitHub Actions upload step

Use [tests workflow](../.github/workflows/tests.yml) with these key steps:

```yaml
- name: Run tests with pytest
  run: uv run pytest --cov=ottu --cov-report=xml --cov-report=term-missing

- name: Upload coverage to Coveralls
  if: matrix.python-version == '3.12'
  uses: coverallsapp/github-action@v2
  with:
    file: ./coverage.xml
    format: cobertura
    github-token: ${{ secrets.GITHUB_TOKEN }}
```

Notes:

1. The `if` condition avoids duplicate uploads from each Python version in the matrix.
2. `coverage.xml` generated by `pytest-cov` is Cobertura format, so `format: cobertura` is correct.
3. `secrets.GITHUB_TOKEN` is enough for most GitHub-hosted public repository setups.

## 4. Trigger and verify

1. Push a branch and open a pull request (or push directly).
2. Wait for [tests workflow](../.github/workflows/tests.yml) to complete.
3. Open the Coveralls project page and confirm a new build appears.
4. Verify files and line coverage match the CI run.

## Optional: Add a coverage badge

Once reports are flowing, add a badge to [README.md](../README.md) from Coveralls badge settings.

## Troubleshooting

### No coverage uploaded

1. Confirm test step created `coverage.xml` in the repository root.
2. Confirm upload step actually ran (matrix condition matched).
3. Confirm repository is enabled in Coveralls.

### Upload step fails with auth/permission errors

1. Ensure workflow has access to `GITHUB_TOKEN` (default in GitHub Actions).
2. For private repositories, you may need a Coveralls repo token.

If needed, add:

```yaml
with:
  github-token: ${{ secrets.GITHUB_TOKEN }}
  file: ./coverage.xml
env:
  COVERALLS_REPO_TOKEN: ${{ secrets.COVERALLS_REPO_TOKEN }}
```

And store `COVERALLS_REPO_TOKEN` in repository secrets.

### Coverage is reported multiple times

If the workflow uses a Python matrix, keep upload restricted to one entry (for example `3.12`) or use Coveralls parallel/finalize mode.

### Coverage values differ from local runs

1. Ensure the same command is used locally and in CI.
2. Ensure all tests are collected in both environments.
3. Check for environment-specific conditional logic in tests.

## Local verification command

You can generate coverage locally using:

```bash
uv run pytest --cov=ottu --cov-report=xml --cov-report=term-missing --cov-report=html
```

Then open `htmlcov/index.html` to inspect per-line details.
