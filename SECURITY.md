# Security Policy

## Supported Versions

The project maintainers will review security reports for the versions currently
under active development. Please check the repository's release status and use
current mainline code for reporting issues.

| Version | Supported |
| ------- | --------- |
| main / latest | Yes |
| older released versions | Not guaranteed |

## Reporting a Vulnerability

If you believe you have found a security vulnerability in this project, please
report it privately and responsibly.

Please email the maintainers at: maker@infineon.com

When reporting, include:

- a clear description of the vulnerability
- affected version or branch
- steps to reproduce the issue
- the impact and risk assessment
- any proposed fix or mitigation

Please do not open a public GitHub issue for security problems until the issue has
been triaged and a fix or mitigation is available.

## Response Expectations

We will make every effort to acknowledge your report promptly and to work with
you to understand and remediate the issue. We ask for reasonable time to assess
and address the report before public disclosure.

## Disclosure Policy

We follow a coordinated disclosure process. Once a fix is available, we may
publish a security advisory or release notes describing the issue and the
mitigation, while keeping sensitive details limited to the minimum necessary.

## Security Best Practices

When contributing to the project:

- do not introduce unsafe patterns or insecure defaults
- validate inputs and handle errors securely
- avoid exposing secrets or credentials in code, logs, or documentation
- report potential vulnerabilities privately as described above
